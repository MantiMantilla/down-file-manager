# Down

A GNOME Files–style file manager for macOS 26+, written in Swift with AppKit and SwiftUI.

- Nautilus-like layout: sidebar, a header bar with an editable path bar, and a floating selection overlay
- GNOME shortcuts translated for macOS (Ctrl → ⌘, Alt → ⌥), all remappable
- Drag and drop with any app. While dragging, hover over a folder, a sidebar entry or a breadcrumb to spring-load into it.
- Copy / cut / paste files, compatible with Finder's pasteboard
- System / Light / Dark themes, pinned folders, external drives with eject, Open in Terminal
- Built-in Debug Console (Settings → Advanced) with live logs, tab state and performance timings

> Status: early development (milestones 1–3 of 9). Grid and column views, the full file-operation queue
> (conflict dialog, progress, undo), Quick Look, search and tabs polish are still to come.

## Build and run

Requirements: macOS 26 and Xcode 27 (the Command Line Tools alone are not enough). Down has no third-party dependencies.

```bash
make run          # debug build, launches in the foreground with debug logs on stderr
make app          # release build → build/Down.app
make install      # → ~/Applications/Down.app and ~/.local/bin/down
make test         # unit + ViewModel + in-process AppKit tests (swift test)
make check        # make test + the String Catalog check; run it before opening a PR
make test-integration   # adds real-filesystem tests (temp dirs, FSEvents, copyfile)
make test-xcode   # the same tests through the Xcode scheme
make test-tsan    # unit + integration tests under Thread Sanitizer
```

The Makefile builds with `xcodebuild` into `build/xcode` and copies the app to `build/Down.app`. It uses the Xcode chosen with `xcode-select` (falling back to `/Applications/Xcode.app` when that is the Command Line Tools), or `DEVELOPER_DIR` if set. `make app` builds for this Mac's architecture only.

### Xcode

Open `Down.xcodeproj`. The modules live in the Swift package (`Package.swift`, `Sources/`, `Tests/`). The project adds only a thin app target: `App/main.swift`, the asset catalog, and `Resources/Info.plist` and `Resources/Down.entitlements`. The shared `Down` scheme runs the app with `--log-level debug` and runs the package's tests. `swift build` and `swift test` also work on the package directly.

The app icon in `App/Assets.xcassets` is a **placeholder**, generated by `swift scripts/make-placeholder-icon.swift`.

### Signing

Signing settings live in `Config/Down.xcconfig`. By default builds are signed ad-hoc ("Sign to Run Locally"). Release builds still get the hardened runtime and no `get-task-allow`.

macOS remembers privacy grants (Desktop, Documents, external drives) per code signature. An ad-hoc signature changes on every build, so you're asked again after each rebuild. To keep the grants, copy `Config/Local.xcconfig.example` to `Config/Local.xcconfig` (git-ignored) and enable one option:

- **A free personal team.** Add your Apple ID in Xcode → Settings → Accounts, then set `DEVELOPMENT_TEAM`. Don't commit a team ID.
- **A self-signed identity** in your login keychain, created with `scripts/make-dev-cert.sh`. The Makefile picks it up on its own when there's no `Local.xcconfig`; you only need option B to use it from Xcode. `DOWN_SIGN_IDENTITY="…" make app` signs with any other identity.

Switching identity changes the app's code requirement, so macOS asks for each permission once more. To clear the stale grants, run `tccutil reset All app.down.Down`.

## Launching from a terminal

`open Down.app` detaches the process, so its log output never reaches your terminal. Use the shim instead:

```bash
down ~/src --log-level debug          # or DOWN_LOG=debug,ops=trace down
down --debug                          # Debug Console + verbose logging for this session
down --snapshot /tmp/down.png         # render the window to a PNG and quit (bug reports)
```

Unified log: `log stream --predicate 'subsystem == "app.down"' --level debug` (file paths are redacted there).

## Shortcuts

| Action | Keys | Action | Keys |
|---|---|---|---|
| Location entry | ⌘L, or type `/` `~` | Back / Forward / Up | ⌥← ⌥→ ⌥↑ |
| Open | ↩, ⌘O, ⌥↓ | Home | ⌥Home, ⇧⌘H |
| Hidden files | ⌘H, ⇧⌘. | Reload | ⌘R, F5 |
| New tab / window / close | ⌘T ⌘N ⌘W | Tab N | ⌥1…9 |
| Copy / Cut / Paste | ⌘C ⌘X ⌘V | Pin current folder | ⌘D |
| Toggle sidebar | F9 | Open in terminal | ⌘⌥T |
| First / last item | Home, End (fn←, fn→) | Page up / down | PgUp, PgDn (fn↑, fn↓) |
| Debug Console | ⌥⌘J (when enabled) | Settings | ⌘, |

Home, End, Page Up and Page Down move the selection (not just the scroll position), like GNOME Files. Add ⇧ to extend the selection.

⌘H shows hidden files (GNOME's Ctrl+H), so "Hide Down" in the app menu has no shortcut.

## Architecture

MVVM with one-way data flow: **View → Action → ViewModel → State → View**.

- `DownCore`: models, services (actors behind protocols), logging. It imports no AppKit or SwiftUI.
  - Listing uses `getattrlistbulk(2)` through a small C shim (`CDirent`) and streams batches.
  - Live updates come from FSEvents (`DirectoryWatcher`).
  - Sorting uses precomputed natural-order collation keys.
- `DownUI`: `@MainActor @Observable` ViewModels, plus AppKit views (list, sidebar, path bar) and SwiftUI (settings).
  - Each ViewModel has a single `send(_:)` mutator. Slow work runs as keyed effects whose results come back as actions.
- `DownTestSupport`: fakes (`FakeFileSource`, `FakeWorkspace`), `TempDir`, `TestLogSink`.

## Localization

Every user-facing string goes through a String Catalog. English is the only language so far.

- `Sources/DownCore/Localizable.xcstrings` and `Sources/DownUI/Localizable.xcstrings` hold each module's strings. They are compiled into the `Down_DownCore.bundle` and `Down_DownUI.bundle` resource bundles inside `Down.app`. For now only the English plural rules end up in there: the key is the English text, and it's used as is until a translation exists.
- `App/InfoPlist.xcstrings` holds the privacy usage descriptions. `Resources/Info.plist` keeps the English text, and a test checks that the two match.

### Writing strings

- Use `String(localized: "Move to Trash", bundle: .module, comment: "File menu and context menu")`. Without `bundle: .module`, the lookup goes to the app's main bundle: it still shows the English key, but it never gets translated.
- Short strings (three words or fewer) need a comment that says where they appear. A test enforces this.
- In SwiftUI, pass that `String` to the view, as in `Toggle(String(localized: …, bundle: .module), isOn: …)`. A bare literal, as in `Text("…")`, is looked up in the main bundle too. Use `Text(verbatim:)` for text that isn't translated.
- Write whole sentences with interpolations, such as `"“\(name)” selected"`. Don't concatenate fragments. Use plural variations in the catalog for counts.
- File names inserted into text go through `DisplayName.sanitize`.
- Strings shown in several places live once in `UIStrings` (DownUI). Command titles come from `Command.title`.
- Not translated:
  - command raw values and settings keys;
  - log messages and the diagnostics report;
  - the Debug Console's internals;
  - product names.

  End a line with `// l10n-ignore` if a lint test flags one of these.

### Keeping the catalogs in sync

Building doesn't update the catalogs. After adding, changing or removing strings:

```bash
make l10n-sync    # merges the strings used in code into the catalogs (adds keys, drops unused ones)
make l10n-check   # fails if the catalogs are out of date; part of `make check`
```

The keys are the English text. If the same English text means different things in two places, `l10n-check` reports the clashing comments. Give one of them a semantic key: `String(localized: "sidebar.section.other", defaultValue: "Other", bundle: .module, comment: …)`.

`LocalizationLintTests` (part of `make test`) flags localized strings without `bundle:`, and literals passed directly to titles, labels, tooltips, alerts or SwiftUI views.

### Checking layout

```bash
make l10n-pseudo  # build/l10n/{accented,double}*.png: main window, sidebar, path bar, Settings
```

The snapshots use Xcode's pseudolanguages. In the accented one, text that isn't accented bypasses the catalogs. Exceptions: system-provided names, such as standard folders and file kinds, and file names. The double-length one shows truncation and clipping. Plural strings look garbled in both, which is a Foundation quirk with pseudolanguages. In Xcode, choose a pseudolanguage under the scheme's Run → Options → App Language.

## Security

- Hardened runtime with no entitlement exceptions. Down is not sandboxed: a general-purpose file manager can't work inside the App Sandbox.
- No shell strings anywhere. Files open through LaunchServices, and Open in Terminal hands the folder to the terminal app (no AppleScript).
- Copies use `copyfile(3)`: they clone on APFS, keep quarantine and other extended attributes, never follow symlinks, and never overwrite existing files.
- File names containing control characters or bidi overrides are shown with visible escapes.
